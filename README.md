# gha-indie-worker-sidecar.rs

Sidecar for GHA Indie Worker.

Inherits [`ores-otel-sidecar`](https://github.com/ores-otel/ores-otel-sidecar.rs).
Bind with `GHA_INDIE_WORKER_SIDECAR_BIND` (default `127.0.0.1:9090`).

```sh
cargo run --bin ghaiw-sidecar
```

Env keys for the normal service mode are centralized in `.cli-flags.toml` and generated by `f2e generate` into `generated/{rust,dart,typescript,gleam}`.

## Live build-log pipe mode

When the worker starts this binary with
`GHAIW_LOG_SIDECAR_PROTOCOL=gha-indie-worker.log-sidecar.v1`, the process switches from HTTP sidecar service mode into a one-command pipe receiver:

- stdin / FD 0 receives versioned binary `GHLG` frames;
- FD 3 receives newline-delimited JSON lifecycle metadata;
- stdout/stderr remain receiver diagnostics/output surfaces;
- EOF closes the receiver cleanly.

Each data frame is `GHLG` + version byte `1` + stream byte (`1` stdout, `2` stderr) + a 32-bit big-endian payload length + raw payload bytes. The decoder is binary-safe and rejects malformed, unsupported, truncated, or oversized frames.

The worker's ordinary stdout/stderr remain authoritative and are written independently before the non-blocking sidecar enqueue. A slow or crashed receiver therefore cannot stall normal build logging. The worker caps sidecar shutdown/drain at eight seconds.

This repository is the reference decoder. Operators can configure `gha-indie-worker.rs` to start any executable implementing the same stdin + FD 3 contract and forward logs to their own OpenTelemetry/Loki/Supabase/Kafka/NATS/object-storage pipeline.

The FD 3 transport is Unix-only for now. A native Windows named-pipe/handle transport should use the same logical v1 events without pretending FD inheritance is portable.
